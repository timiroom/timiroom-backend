# 문제 정의 (Problem Statement)

**목적**: 해결해야 할 문제를 명확하고 측정 가능하게 정의한다.

**How Might We (HMW) 프레임**:
"[타겟 사용자]가 [맥락]에서 [목표]를 달성할 수 있도록 어떻게 하면 [문제]를 해결할 수 있을까?"

**5 Whys 분석**:
- 표면적 문제에서 시작하여 "왜?"를 5번 반복
- 근본 원인(Root Cause) 도출

**문제 정의 체크리스트**:
- [ ] 누가 이 문제를 겪는가? (타겟 명확화)
- [ ] 언제/어디서 이 문제가 발생하는가? (맥락)
- [ ] 이 문제로 인한 실질적 피해는? (임팩트 정량화)
- [ ] 현재 어떻게 해결하고 있는가? (현재 대안)
- [ ] 현재 대안의 한계는? (기회 영역)

**좋은 문제 정의 예시**:
"한국 소상공인의 68%는 재고 관리를 엑셀로 하며 월 평균 8시간을 낭비한다. (출처: 소상공인시장진흥공단, 2023년) 실수로 인한 재고 오차로 매출 손실이 발생하지만, 기존 ERP는 도입 비용이 300만원 이상이어서 접근이 어렵다."

**피해야 할 패턴**:
- 솔루션을 문제로 포장 ("우리는 앱이 필요하다")
- 막연한 표현 ("사용자 경험이 나쁘다")
