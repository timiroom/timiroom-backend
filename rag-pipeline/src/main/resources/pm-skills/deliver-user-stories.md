# 사용자 스토리 (User Stories)

**목적**: 기능을 사용자 관점의 가치 중심으로 표현하여 개발팀과 공통 언어를 만든다.

**기본 형식**:
"나는 [역할]로서 [목적/이유]를 위해 [기능/행동]을 하고 싶다."

**INVEST 원칙**:
- Independent: 다른 스토리와 독립적으로 개발·테스트 가능
- Negotiable: 구현 방법은 협의 가능
- Valuable: 사용자에게 명확한 가치 제공
- Estimable: 개발 규모 추정 가능
- Small: 한 스프린트 내 완료 가능
- Testable: 완료 기준 명확

**인수 기준 (Acceptance Criteria) 작성**:
Given [초기 상태] / When [사용자 행동] / Then [기대 결과]

**예시**:
- 스토리: "나는 판매자로서 재고 현황을 실시간으로 확인하기 위해 재고 대시보드를 보고 싶다."
- AC1: Given 로그인 상태, When 대시보드 진입, Then 상품별 현재 재고 수량이 표시된다.
- AC2: Given 재고 5개 이하, When 대시보드 확인, Then 해당 상품에 경고 알림이 표시된다.

**에픽 → 스토리 분해**:
- 에픽: 대규모 기능 (예: "결제 시스템")
- 스토리: 에픽을 1~3일 단위로 분해 (예: "카드 결제", "간편결제", "결제 취소")
