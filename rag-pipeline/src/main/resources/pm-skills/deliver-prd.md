# PRD (Product Requirements Document) 작성

**목적**: 투자자·개발팀이 신뢰할 수 있는 제품 요구사항 문서를 작성한다.

**핵심 섹션**:
1. **배경(Background)**: 시장 현황 → 문제점 → 기회. 실제 수치와 출처 필수.
2. **목표(Goals)**: "~을 통해 ~을 달성하여 ~에 기여" 형식, 4개 이상.
3. **KPI**: 현재값 → 목표값, 측정 방법, 외부 출처 포함. 7개 이상.
4. **경쟁사 분석**: 강점/약점/차별화 포인트, 한국 서비스 5개 이상.
5. **핵심 기능(coreFeatures)**: featureList 1:1 매핑, 100자 이상 설명.
6. **릴리즈 일정**: 마일스톤 6개 이상, Done Criteria 포함.
7. **기능 상세(FSD)**: 12개 이상, "사용자가 ~상황에서 ~할 수 있어야 한다."
8. **운영 정책**: 8개 이상, 서로 다른 법령 조항 명시.
9. **리스크**: 5개 이상, 발생 트리거·피해 범위·대응 절차.
10. **성공 지표(successMetrics)**: KPI와 1:1 대응, 측정 도구 명시.

**품질 원칙**:
- 출처 없는 수치 사용 금지
- "내부 목표", "내부 설문" 표현 금지
- 단순 키워드 나열 금지 — 완성된 문장으로 작성
- "누가/무엇을/어떻게/왜" 구조 유지
