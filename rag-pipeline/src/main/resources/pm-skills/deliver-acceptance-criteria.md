# 인수 기준 (Acceptance Criteria)

**목적**: 기능 완료를 판단하는 명확하고 테스트 가능한 기준을 정의한다.

**Gherkin 형식** (권장):
```
Given [사전 조건 — 시스템/사용자 초기 상태]
When [사용자 행동 또는 이벤트]
Then [기대되는 시스템 반응 또는 결과]
And [추가 결과 조건]
```

**좋은 AC 특성**:
- 테스트 가능: QA가 자동/수동 테스트로 검증 가능
- 명확: 해석의 여지 없이 Pass/Fail 판단 가능
- 독립적: 다른 AC에 의존하지 않음
- 가치 중심: 사용자 가치 또는 비즈니스 규칙 반영

**예시**:
```
기능: 재고 부족 알림
Given 상품 재고가 설정한 최소 수량(기본값: 5개) 이하일 때
When 판매자가 재고 관리 화면에 접속하면
Then 해당 상품 행에 주황색 경고 아이콘이 표시되고
And "재고 부족" 뱃지가 표시되어야 한다
And 알림 설정이 ON인 경우 이메일/푸시 알림이 발송되어야 한다
```

**작성 시 피해야 할 것**:
- "잘 동작해야 한다" (측정 불가)
- "빠르게 로딩되어야 한다" (기준 없음 → "3초 이내" 등 수치 명시)
- 구현 방법 명시 ("React로 렌더링" — How, not What)
